# Kakao OAuth Authentication Specification

## Overview
힐(Heal) 커뮤니티 관리 시스템의 **카카오 로그인(Kakao OAuth) 인증 흐름**, **기존 회원 자동 로그인 및 미등록 신규 회원 온보딩 분기 처리**, 그리고 **Kakao Developers 콘솔 설정 규격**을 정의합니다.

Firebase 무료 플랜(Spark)과 유료 플랜(Blaze + Cloud Functions) 모두에서 중단 없이 동작하도록 **Kakao JavaScript SDK 클라이언트 인증 + 선택적 Firebase Custom Token 발급 하이브리드 구조**를 채택합니다.

## Business Rules & Logic

### 1. Kakao Login & Onboarding Routing Flow
1. **기본 세션 정책 (Unauthenticated by Default):**
   - 브라우저 로컬 스토리지에 유효한 회원 UID가 저장되어 있지 않은 첫 접속자는 **비로그인(Guest) 상태(`currentUser = null`)**로 시작합니다.
   - 첫 진입 시 임의의 데모 계정으로 자동 로그인되지 않으며, 공통 로그인/온보딩 화면(`LoginOnboardingPage`)으로 진입합니다.
2. **카카오 인증 단일 진입로 (`Single Login CTA`):**
   - 첫 화면의 별도 '신입 등록' 버튼을 제거하고 **`[카카오 로그인]` 단일 진입로**로 통일합니다.
   - 사용자가 `[카카오 로그인]`을 누르면 Kakao JS SDK(`Kakao.Auth.login`)를 통해 카카오 고유 식별자(`kakao:${id}`)와 닉네임을 조회합니다.
3. **선택적 Cloud Functions 커스텀 토큰 연동:**
   - Firebase Cloud Functions(`kakaoCustomAuth`)가 배포된 환경에서는 카카오 액세스 토큰을 전달해 Firebase Custom Token으로 `signInWithCustomToken`을 수행합니다.
   - 무료(Spark) 플랜 환경에서는 Cloud Functions 호출 실패 시에도 에러 없이 카카오 고유 UID(`kakao:${id}`) 세션으로 즉시 폴백하여 동작합니다.
4. **기존 회원 vs 신규 회원 자동 분기 & 서브폰 자동 인식:**
   - Firestore `members` 컬렉션에서 `uid === "kakao:${id}"` 또는 `subUids.includes("kakao:${id}")`인 본계정이 **이미 존재하는 경우**: 즉시 해당 본계정으로 로그인 완료 처리하고 `[홈]` 화면으로 이동합니다.
   - 본계정 및 서브폰 등록 어디에도 해당 `uid`가 **없는 경우(미등록 신규 또는 미연동 서브폰)**: 카카오 인증 정보를 유지한 채 자동으로 **프로필 등록/온보딩(`step = 'onboarding'`)** 폼으로 전환됩니다.
5. **동명이인 방지 및 온보딩 연동 분기 (이력 승계 vs 서브폰 연동 vs 중복 차단):**
   - **이름 규칙 검증:** 활동 닉네임은 **한글 1자 이상 3자 이하**의 유일한 이름이어야 합니다 (정규식: `/^[가-힣]{1,3}$/`, 동명이인 엄격 금지).
   - **유형 A: 과거 활동 이력 승계 제안 (`linkRequestType: 'historical'`):**
     - 카카오 미연동 상태의 과거 활동 이력 회원(`kakao:10*` 가계정)과 이름이 일치하면 닉네임 필드 아래에 승계 카드(`💡 혹시 이전에 활동하셨던 [이름] 님이신가요? 과거 벙 활동 기록(총 N점, 참석 N회)을 이 카카오 계정으로 연결 신청하시겠습니까?`)가 표시됩니다.
     - 사용자가 `[⚡ 네, 기존 활동 이력 연결 신청하기]`를 누르면 기존 점수/참석 이력이 해당 카카오 계정으로 연결 신청됩니다 (운영진 승인 시 기존 UID에 새 카카오 UID 인계 통합).
   - **유형 B: 현재 활동 회원 일치 시 이원화 분기 (기기변경 vs 서브폰 등록):**
     - 현재 활동 중인 회원과 이름이 일치하는 경우(예: 기존 회원이 새 카톡 계정이나 새 기기로 접속 시), 이름 필드 아래에 선택 안내 카드(`💡 혹시 [이름] 님이신가요? (기기변경 또는 서브폰)`)가 표시되며 2가지 버튼을 제공합니다:
       1. **`[🔄 기기변경 (새 폰으로 기존 계정 완전 승계)]` (`linkRequestType: 'historical'`):** 휴대폰 교체, 번호 변경, 카카오 계정 재가입 등으로 기존 폰을 더 이상 안 쓰는 경우. 운영진 승인 시 `reassignMemberUid`를 통해 기존 계정의 누적 점수, 출석 횟수, 주최 횟수, 벙 참여 이력, 관리자 권한이 새 카카오 UID로 100% 완전 이전되며 이전 계정 UID는 새 UID로 교체 삭제됩니다.
       2. **`[📱 서브폰 등록 (기존 폰과 함께 복수 기기 사용)]` (`linkRequestType: 'subPhone'`):** 세컨폰이나 업무용 기기 등으로 기존 폰도 계속 쓰면서 새 폰도 함께 쓰는 경우. 운영진 승인 시 본계정의 `subUids` 배열에 추가되어 양쪽 기기 모두에서 동시 로그인 및 활동이 가능합니다.
   - **유형 C: 보조 닉네임(별칭) 서브폰 연동:**
     - 본계정과 서브폰의 활동 닉네임이 다른 경우(예: 본계정 `카일` - 서브폰 `카이`), 온보딩 화면의 **'직접 계정 찾기'** 드롭다운에서 본인의 본계정을 선택하여 서브폰 연결을 신청합니다. 이 경우 보조 닉네임(`linkRequestSubName: '카이'`)이 함께 등록 신청됩니다.
   - **유형 D: 단순 중복 이름 경고 및 가입 차단:**
     - 타인의 계정과 중복되는 이름인데 승계나 서브폰 연동 대상이 아닌 순수 신규 가입자인 경우, `⚠️ 이미 등록된 이름이므로 다른 이름(한글 1~3자)을 사용해 주세요` 경고와 함께 `[저장 후 입장]`이 엄격히 차단됩니다.
6. **서브폰 운영진 승인 및 자동 통합 프로세스:**
   - 사용자가 서브폰 연동을 신청하면 신청 문서가 `status: 'pending'`, `linkRequestStatus: 'pending'`, `linkRequestType: 'subPhone'` 상태로 생성됩니다.
   - 운영진 페이지(`AdminPage > 요청`)에서 **`[📱 승인 (본계정에 서브폰 등록)]`**을 탭하면:
     1. 본계정의 `subUids` 배열에 신청자의 카카오 UID가 추가됩니다.
     2. 보조 닉네임이 있는 경우 본계정의 `aliases` 배열에 추가됩니다.
     3. 서브 거주지가 본계정과 다른 경우 `subCities` 배열에 추가됩니다.
     4. 임시 신청자 문서는 컬렉션에서 안전하게 삭제 정리됩니다.
   - 이후 해당 서브폰 기기로 로그인 시 온보딩을 거치지 않고 본계정으로 즉시 로그인됩니다.
7. **필수 입력값 검증:**
   - 한글 1~3자의 유일한 이름, 거주 지역, 결혼 여부, 성별이 모두 유효하게 입력되지 않으면 `[저장 후 입장]` 버튼이 비활성화(`disabled`)됩니다.

### 2. Kakao Developers Console Required Settings (필수 콘솔 설정 3가지)
발급받은 JavaScript 키(`VITE_KAKAO_JS_KEY`)로 브라우저에서 카카오 로그인이 정상 동작하려면 [Kakao Developers](https://developers.kakao.com/) 내 애플리케이션 설정에서 아래 3가지가 반드시 설정되어 있어야 합니다.

1. **웹 플랫폼 도메인 등록:**
   - 좌측 메뉴 **`[앱 설정] → [플랫폼]`** (또는 **`[앱] → [플랫폼 키] / [일반]`** 하위 Web 플랫폼 등록) 이동
   - **[Web 플랫폼 등록]** 클릭 → 사이트 도메인에 아래 주소 등록:
     - `http://localhost:3000`
     - `http://172.30.1.29:3000` (동일 Wi-Fi 모바일 테스트용)
     - `https://healing78.web.app` (추후 Firebase Hosting 배포 도메인)
2. **카카오 로그인 활성화 설정 ON:**
   - 좌측 메뉴 **`[제품 설정] → [카카오 로그인]`** 이동
   - **활성화 설정**의 상태를 **`ON`**으로 변경
   - 하단 **Redirect URI**에 `http://localhost:3000` 추가 등록
3. **동의항목 설정:**
   - 좌측 메뉴 **`[제품 설정] → [카카오 로그인] → [동의항목]`** 이동
   - `닉네임 (profile_nickname)` 항목을 **선택 동의**(또는 필수 동의)로 설정

### 3. Kakao Login Access Log Tracking & Admin Monitoring (접속 이력 추적 및 신입 모니터링)
- **카카오 인증 시 접속 기록 자동 수집 (`recordKakaoLogin`):**
  - 사용자가 카카오 로그인을 성공할 때마다(신규 가입자 및 기존 회원 공통) Firestore `loginLogs` 컬렉션 및 로컬 저장소에 접속 일시(`lastLoginAt`), UID(`uid`), 접속 횟수(`loginCount`)가 실시간 누적 기록됩니다.
- **운영진 전용 로그인 접속 현황 탭 (`AdminPage > 로그인`):**
  - 운영자 탭 내 신설된 `[로그인]` 서브탭에서 카카오 로그인을 진행한 모든 사용자의 상세 이력을 실시간 모니터링할 수 있습니다:
    1. **날짜:** 최근 접속 일시 (YYYY-MM-DD HH:mm 포맷)
    2. **UID:** 카카오 식별자(`kakao:...`) 및 원클릭 UID 복사 도구
    3. **이름:**
       - **가입 완료 회원:** 등록된 활동 닉네임 및 실명 표시
       - **로그인 후 가입 미완료 사용자:** 사용자 프라이버시 보호 및 미등록 상태 구분을 위해 **이름을 제외**하고 `(미가입 회원 - 이름 제외)`로 표시
    4. **접속 횟수:** 해당 UID의 누적 로그인 횟수
    5. **상태 필터링:** `전체`, `미가입`, `가입완료` 빠른 토글 필터 및 검색 지원

### 4. Developer Tools: Onboarding & Sub-Phone Simulator Sandbox (디버깅 도구 및 샌드박스)
- **도입 배경:**
  - 최고관리자(`카일`, `kakao:5166442426`)가 한 번 카카오 로그인을 진행하면 브라우저에 카카오 세션이 유지되고, 기존 등록 회원으로 자동 인식되어 신규 회원 온보딩 화면(`step = 'onboarding'`)에 재진입하기 어려웠던 디버깅 제약을 해소합니다.
- **실행 경로 2가지:**
  1. **마스터 탭 내 원클릭 실행 (`SuperAdminPage`):** `[🚀 온보딩 시뮬레이터 즉시 실행]` 버튼을 클릭하면 현재 관리자 로그인을 유지한 채 가상 카카오 사용자(`kakao:sim-...`) 모드로 온보딩 화면이 즉시 열립니다.
  2. **URL 파라미터 직행 (`/?debug=onboarding`):** 브라우저 주소창에 `?debug=onboarding` 파라미터를 입력하거나 로그인 화면 하단의 시뮬레이터 링크를 클릭하면 즉시 온보딩 폼으로 진입합니다.
- **시뮬레이션 데이터 격리 및 3단계 안전장치:**
  1. **식별 뱃지:** 시뮬레이터로 생성된 계정은 UID가 `kakao:sim-...`으로 부여되고 `isSimulation: true` 플래그가 설정되며, 운영진 페이지(`AdminPage > 요청`)에 `🧪 시뮬레이션` 뱃지가 함께 표시됩니다.
  2. **반려 시 자동 영구 삭제:** `AdminPage`에서 `[❌ 반려]`를 누르면 임시 테스트 계정이 Firestore 및 로컬에서 즉시 영구 삭제됩니다.
  3. **승인 후 안전 분리 & 일괄 정리:** 승인 테스트 완료 후에도 본인의 `내 정보 > 📱 연결된 서브폰`에서 `[연결 해제]`하거나, 마스터 관리 센터에서 **`[🧹 테스트 데이터 정리]`**를 누르면 모든 `kakao:sim-*` 계정이 본계정의 `subUids` 배열 및 DB에서 원클릭으로 일괄 정리됩니다.

## Data Schema & API

### Kakao Auth Profile Response (`src/services/kakaoAuthService.js`)
```javascript
/**
 * @typedef {Object} KakaoAuthResult
 * @property {string} uid - Firebase/Firestore 표준 회원 UID (예: 'kakao:381920391')
 * @property {string} kakaoId - 카카오 원본 숫자 ID 문자열
 * @property {string} nickname - 카카오톡 프로필 닉네임
 * @property {string} accessToken - 카카오 OAuth 액세스 토큰
 */
```

## Edge Cases & Validation
- **도메인 미등록(`KOE006` / `KOE101`) 또는 카카오 로그인 미활성화(`KOE004`) 에러:**
  - 사용자가 Kakao Developers 콘솔에서 아직 `http://localhost:3000` 도메인 등록이나 활성화 `ON` 스위치를 켜지 않은 상태에서 로그인을 시도할 경우, 화면에 구체적인 해결 방법을 안내 배너로 표시합니다.
- **팝업 차단 브라우저 대응:**
  - 모바일 인앱 브라우저 등에서 팝업이 차단된 경우 사용자에게 팝업 허용 안내를 표시하거나 온보딩 체험 모드로 즉시 진입할 수 있는 보조 버튼을 함께 제공합니다.

## Test Scenarios
1. **신규 카카오 계정 최초 로그인 검증:**
   - `[카카오 계정으로 로그인]` 클릭 → 카카오 인증 완료 → `members`에 없는 신규 `kakao:${id}`인 경우 자동으로 온보딩(프로필 설정) 폼으로 이동하는지 확인.
   - 온보딩 폼 입력 완료 후 저장 시 Firestore `members` 컬렉션에 `kakao:${id}` 문서가 생성되고 `일반회원(Member)`으로 입장하는지 확인.
2. **재로그인 시 즉시 입장 검증:**
   - 이미 온보딩을 마친 동일 카카오 계정으로 다시 로그인했을 때 온보딩 화면을 건너뛰고 바로 `[홈]` 화면으로 진입하는지 확인.
3. **서브폰 온보딩 연동 신청 및 운영진 승인 검증:**
   - 시뮬레이터 또는 신규 기기에서 활동 회원(예: `뽀야`, `지민`)의 이름 입력 시 서브폰 연동 안내 카드가 노출되는지 확인.
   - `[📱 네, [이름] 님의 서브폰으로 연결 신청하기]` 후 신청 완료 → `AdminPage > 요청`에 `📱 서브폰 연동 요청` 뱃지와 함께 신청서가 노출되는지 확인.
   - 운영진 `[📱 승인]` 클릭 시 본계정의 `subUids` 배열에 해당 UID가 등록되고 신청 임시 문서는 자동 삭제되는지 확인.
   - 이후 해당 서브폰 UID로 접속 시 본계정으로 즉시 로그인되는지 확인.
4. **시뮬레이션 모드 및 안전한 테스트 데이터 정리 검증:**
   - 마스터 탭에서 `[🚀 온보딩 시뮬레이터 즉시 실행]` 또는 `/?debug=onboarding` 접속 시 가상 UID(`kakao:sim-...`)로 온보딩이 실행되는지 확인.
   - 테스트 후 `SuperAdminPage > [🧹 테스트 데이터 정리]` 실행 시 모든 시뮬레이션 데이터가 깔끔하게 삭제 정리되는지 확인.
