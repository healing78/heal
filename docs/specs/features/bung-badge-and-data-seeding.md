# Bung Badge System & Historical Data Seeding Specification

## Overview
본 문서는 Healing78 커뮤니티의 공식 벙기록 아카이브(852회 이상)를 바탕으로 확립된 **마일스톤 뱃지 체계(Milestone Badge Tier)** 및 **역사적 벙기록 초기 데이터 주입(Seeding)과 실시간 동기화 환경**에 관한 기술 명세입니다.

## Business Rules & Logic

### 1. 벙점수 (Bung Score) 산정 규격
벙(모임) 참석을 통해 생성·부여되는 모든 점수를 통틀어 **`벙점수`**라고 명칭합니다. 벙점수는 기본 출석 점수와 권역별 원정 가산점으로 구성되며, 회원의 누적 마일스톤 티어 뱃지를 산정하는 핵심 기준입니다.

- **기본 벙점수**: 모임 참석 확정 시 **+1점** (`baseScore`)
- **타 권역 원정 벙점수**: 회원의 거주 도/권역과 다른 도의 모임 참석 시 **+1점 추가 (총 2점)** (`expeditionScore`)
  - 서울·경기는 단일 권역으로 취급 (서울, 경기, 인천)
  - 충청권은 남도/북도 및 대전·세종 통합 취급
  - 전라권은 남도/북도 및 광주 통합 취급
  - 경상권은 남도/북도 및 부산·대구·울산 통합 취급
  - 강원도, 제주도 각각 독립 권역
- **해외 친구/원정 벙점수**: 해외 거주자 참석 또는 해외 모임 1회 참석 시 **+2점 추가 (총 3점)**
- **누적 벙점수 계산 (`totalScore`)**:
  - `누적 벙점수 = 기본 벙점수(baseScore) + 원정 벙점수(expeditionScore) + 이벤트 점수(eventScore)`
  - 마감 탭 및 랭킹 페이지에서는 항상 이 기준에 따라 벙점수 시작 위치와 변화량을 일관되게 표출합니다.

### 2. Milestone Badge Tier Rules (금은동 및 동물 뱃지 체계)
회원의 누적 벙점수(`totalScore`)에 따라 아래 마일스톤 뱃지가 자동 산정되어 규격 닉네임 뒷자리에 부여됩니다.
500점 단위로 별(`⭐️`)이 누적되며, 메달과 동물이 순환 결합됩니다.

| 최소 점수 | 뱃지 | 설명 |
| :--- | :--- | :--- |
| **15점** | 🦓 | 멈춰있는 얼룩말 |
| **30점** | 🐎 | 달리는 말 |
| **50점** | 🐴 | 대왕말 |
| **78점** | 🦄 | 유니콘 |
| **100점** | 🥉 | 동메달 |
| **200점** | 🥈 | 은메달 |
| **300점** | 🥇 | 금메달 |
| **400점** | 🏆 | 트로피 |
| **500점** | ⭐️ | 별 (1개) |
| **600점** | ⭐️🥉 | 별 1개 + 동메달 (500단위 반복 순환) |

#### 결합 계산식:
- `starCount = Math.floor(totalScore / 500)`
- `rem500 = totalScore % 500`
- 메달: `rem500 >= 400 ? '🏆' : rem500 >= 300 ? '🥇' : rem500 >= 200 ? '🥈' : rem500 >= 100 ? '🥉' : ''`
- 동물: `rem100 = rem500 % 100` 기준 `>= 78 ? '🦄' : >= 50 ? '🐴' : >= 30 ? '🐎' : >= 15 ? '🦓' : ''`
- 결합 예시:
  - 115점: `🥉🦓` (동메달 + 얼룩말)
  - 278점: `🥈🦄` (은메달 + 유니콘)
  - 360점: `🥇🐴` (금메달 + 대왕말)
  - 450점: `🏆🐴` (트로피 + 대왕말)
  - 600점: `⭐️🥉` (별 1개 + 동메달)
  - 15점 미만: 기본 가입일 뱃지(`entryBadge`, 예: `0829`) 또는 기본값 노출

## Data Schema & API

### 1. Seeding Data Files
- **`src/core/initialData.js`**:
  - `INITIAL_MEMBERS`: 142명 이상의 실제 벙기록 회원 데이터 (누적 점수, 참석 횟수, 원정 점수, 주최 횟수 등 정밀 반영)
  - `INITIAL_MEETINGS`: 최근 60개 모임의 참석자, 차수, 정산 상태가 복원된 모임 목록
  - `INITIAL_COMMUNITY_CONFIG`: 뱃지 체계 및 거리 가산점 안내 문구가 반영된 기본 설정
- **`scripts/data/full_bung_data.json`**:
  - 총 852회 전체 벙기록과 270명 전체 참여 인원이 포함된 완전 백업 아카이브 JSON

### 2. Synchronization APIs & Tools
- **CLI Script**: `npm run seed:bung` (`scripts/seed-bung-records.mjs`)
- **Service API**: `batchSyncCommunityData(members, meetings, config)`

### 3. Historical Data Integrity Patch History
- **'잔치' (`kakao:1121`, 창원) 벙 참석 점수 보정:**
  - **원인:** 과거 원천 텍스트 기록(`raw_bung_doc.txt`) 상단 요약표의 오타(`2 : ... 잔치(0) ...`)로 인해 총점 2점임에도 참석 횟수 0회(`attendanceCount: 0`), 원정 2점으로 기형 파싱되었음.
  - **확인:** 실제 2026년 8월 15일 벙 기록에 `잔치2`로 정상 참석하여 2점(기본 1점 + 원정 1점)을 획득한 이력이 존재함.
  - **보정:** `attendanceCount: 1`, `baseScore: 1`, `expeditionScore: 1`, `totalScore: 2`로 원천 및 런타임 데이터 영구 정상화 완료.
- **'다온' (`kakao:1013`, 전주) 프로필 정보 정상화:**

  - **확인:** 실제 벙 참석 이력(광주/전주권 정기 모임 주최 및 참석, 타 권역 이동 시 원정 가산점 획득) 및 회원 정보 대조 확인 완료.
  - **보정:** `city: '전주'`, `homeCity: '전주'`, `maritalStatus: 'divorced'`(돌), `gender: '여'`로 정상화하여 규격 닉네임 `다온 전주 돌 여`로 일원화 완료.

### 4. Strict Real-Data Integrity Principle (가상 데이터 배제 및 원천 데이터 순수성)
- **무작위 총무 지정 전면 배제:**
  - 원천 벙기록 텍스트에 총무가 명시되지 않은 모임에 임의로 참석자 중 1명을 총무(`treasurerUid`)로 자동 지정하던 로직을 전면 제거하고 `""`(공백)으로 처리.
- **가상 좋아요 데이터 전면 제거:**
  - 시드 주입 시 참석자 3명을 임의로 `likes`에 넣어두던 가상 좋아요 데이터를 전면 초기화(`likes: []`).
- **일괄 회비 산정 데이터 전면 제거:**
  - 실제 영수증 정산이 없는 벙기록에 `인원수 * 20,000원`으로 일괄 산정되던 차수 비용(`cost`) 및 가상 결제 확인 상태(`paymentStatuses`)를 `cost: 0`, `payerUid: ""`, `paymentStatuses: {}`로 전면 정상화.
- **가상 데모 데이터 및 비실제 데이터 삭제:**
  - 초기 시드 및 Firestore에 포함되었던 비실제 테스트 모임(8건), 가상 점수 로그(6건), 임의의 가상 계좌번호(`3333-01-1234567` 등)를 전면 삭제.
  - 오직 854건의 실제 벙기록과 281명의 실제 회원 데이터만 순수하게 유지.
  - Firestore의 500건 writeBatch 제한을 방지하기 위해 350건 단위로 청크 분할 커밋
  - LocalStorage 및 Firestore 동시 업데이트
- **SuperAdmin UI Console** (`SuperAdminPage.jsx`):
  - **원클릭 시드 동기화**: `⚡ 공식 벙기록 표준 시드 즉시 동기화`
  - **텍스트 파서 동기화**: `📋 벙기록 텍스트 직접 입력 / 파싱 동기화` (정규표현식 기반 실시간 클라이언트 파싱)

## Edge Cases & Validation
1. **Firestore Batch Limit**: 대량의 회원 및 모임 데이터 저장 시 `350`건 단위로 청크 분할하여 `Transaction too big` 에러 방지.
2. **이름 색상 표기 준수**: 한국 문화 정책에 따라 회원의 실명/닉네임은 `rose` 테마에서도 빨간색으로 표기되지 않고 기본 텍스트 색상을 유지.
3. **15점 미만 신규 회원**: 마일스톤 동물이 부여되지 않으므로 기존 가입일(`entryBadge`, MMDD) 뱃지로 폴백 처리.

## 5. 벙점수 무결성 검증 & 원천 데이터 재계산 시스템 (SSOT Engine)

### (1) 시스템 개요 및 단일 진실 공급원(SSOT) 원칙
- **단일 진실 공급원(SSOT)**: 마감(`isClosed === true` 또는 `status === 'completed'`)된 원천 모임(850+ 건) 기록을 기준으로 모든 회원의 벙점수를 멱등(Idempotent)하게 산출합니다.
- **점수 산출 공식**:
  $$\text{총 점수(totalScore)} = \text{기본 벙점수(baseScore)} + \text{원정 벙점수(expeditionScore)} + \text{이벤트/수동 점수(eventScore)}$$
  - 마감 벙 참석 1회당: 기본점수 1점 (`baseScore += 1`)
  - 마감 벙 벙주(호스트) 1회당: 기본점수 2점 가산 (`baseScore += 2`)
  - 권역 간 원정 참석 1회당: 원정점수 1점 가산 (`expeditionScore += 1`, 모임 권역과 회원 거주 권역이 상이하고 유효한 경우)
  - 이벤트 점수(`eventScore`): 수동 부여 또는 특별 이벤트로 지급된 점수로서 재계산 시 훼손되지 않고 100% 보존됨.

### (2) 4단계 무결성 검증 및 재계산 워크플로우 (방안 A: 마스터 탭 콘솔)
1. **1단계: 원천 데이터 이상치(Anomaly) 검출**
   - 권역 미감지 모임(장소 텍스트에서 4대 권역 파싱 불가) 검출
   - 마감 모임 중 참석자 0명인 모임 검출
   - 거주지 권역 미입력 회원 검출
2. **2단계: Dry-Run 실시간 불일치(Drift) 시뮬레이션**
   - 실제 DB 데이터를 수정하지 않고 가상 메모리 상에서 전체 원천 모임을 날짜순 재계산.
   - 현재 DB의 `totalScore`, `attendanceCount`, `hostCount`, `badge`와 시뮬레이션 결과를 비교하여 오차(Drift) 인원 및 차액을 실시간 분석.
3. **3단계: 안전 일괄 동기화(Safe Sync) & 뱃지 자동 승급**
   - 관리자의 2단계 확인(Armed Action) 후, 원천 모임 기반으로 전 회원 데이터 일괄 갱신.
   - 변동된 `totalScore`에 따라 마일스톤 뱃지(얼룩말, 달리는 말, 당나귀, 유니콘 등)도 일괄 자동 승급/동기화.
4. **4단계: 과거 벙 수정/보정 시 자동 정합성 유지**
   - 과거 벙의 참석자나 장소 오류가 사후 수정되더라도, 마스터 콘솔에서 언제든 1-Click으로 전체 벙점수를 최신 정합 상태로 복원 가능.

## 6. 벙대기실 마감탭(Lounge Closing Tab) 역사적 점수 & 신입 승급 영구 보존 엔진

### (1) 배경 및 핵심 문제 해결
- **문제점**:
  - 마감탭이 회원의 "실시간 최신 총점"에서 벙점수를 단순 차감(`currentScore - earned → currentScore`)하는 방식으로 구현되어 있어, 시간이 흘러 회원이 다른 벙들에 참석해 점수가 누적되면 과거 벙 기록의 점수 변화가 현재 점수로 뭉개져 보이는 왜곡 현상 발생.
  - 신입(Rookie) 회원이 첫 벙을 참석하여 일반 멤버(Member)로 승급하더라도, 단순 `m.role === 'Rookie'` 체크 및 `attendanceCount - 1` 역산으로 인해 차후 다른 벙에 참석하면 과거 첫 벙에서 승급 축하 메시지와 뱃지가 사라지던 결함 해결.
- **해결 방안 (2중 영구 보존 아키텍처)**:
  1. **타임라인 기반 역사적 점수 복원 엔진 (`getHistoricalScoreInfo`)**:
     - 기존 850여 개 전체 과거 벙 기록 열람 시, 전체 모임 타임라인(`allMeetings`)의 날짜/시간 정렬 키(`getMeetingDateTimeSortKey`)를 기준으로 해당 모임 직전까지 획득한 누적 점수(`priorScore`)와 이전 참석 횟수(`priorCount`)를 실시간 역산하여 정확한 당시의 `beforeScore → afterScore` 및 티어 뱃지 획득, 신입 승급(`priorCount === 0`)을 복원.
  2. **마감 시점 영구 스냅샷 박제 (`memberScoreSnapshots` & `rookiePromotedUids`)**:
     - 최종 마감(`settleMeetingWithScores`) 시점에 각 참석자의 `{ beforeScore, afterScore, earned, isRookiePromotion }`을 모임 객체에 영구 스냅샷으로 저장하여 차후 재계산 없이도 즉각 무결하게 열람 가능.
  3. **마감 전(Preview) 모드 지원**:
     - 아직 마감되지 않은 모임에서는 기존 설계 목적대로 현재 점수 기준 마감 후 예상 점수를 정확히 미리보기 제공.
  4. **마감 친구 리스트 행(Row) 직접 뱃지 노출**:
     - 상단 축하 카드뿐만 아니라 하단 참석자 명단 리스트 행에도 `[정회원 승급 🎊]` 및 `[티어 뱃지 달성 ⭐]` 뱃지를 직접 노출하여 시각적 직관성 극대화.
