# 벙대기실 정산탭 및 선입금·정산표 기능 명세서 (Settlement & Advance Deposit Specification)

> **문서 목적:**  
> 벙대기실(`MeetingDetailPage.jsx`)의 정산 탭 구조 개편, 선입금(Advance Deposit) 전체 라이프사이클 관리, 모임 및 개인 정산표, 1열 인라인 찬조금 입력, 비고 실시간 저장, 수동조정 일괄 적용 로직을 영구히 기록하고 유지보수할 수 있도록 표준 사양을 정의합니다.

---

## 1. 정산 탭 3대 아코디언 카드 아키텍처

기존의 4개 영역(나의 회비, 3대 요약 카드, 참석자 목록, 하단 설정 서랍)으로 파편화되어 있던 UI를 **3개의 독립 아코디언 카드**로 통합하였습니다.

```
┌─────────────────────────────────────────────────────────────┐
│ [섹션 1] 나의 회비 아코디언 카드 (기본: 접힘)                  │
│  - Header: 선입금 상태/버튼 | 최종 회비 | [입금 완료] 버튼      │
│  - Body: 내 상세 정산표 (선입금, 차수별, 찬조할인, 수동조정, 총합)│
├─────────────────────────────────────────────────────────────┤
│ [섹션 2] 정산 내역 아코디언 카드 (기본: 접힘)                  │
│  - Header: 총무 입금 계좌 | [계좌 복사] | [내 계좌] 버튼       │
│  - Body: 3개 요약 카드 (총지출, 찬조, 1/N 대상액)              │
│          모임 전체 정산표 (항목, 금액, 내용[뱃지], 비고[실시간])│
│          하단 액션: [+ 찬조 추가] [+ 선입금 추가] [정산서 복사]  │
│          1-Line 찬조/선입금 인라인 폼                        │
├─────────────────────────────────────────────────────────────┤
│ [섹션 3] 개인별 내역 아코디언 카드 (기본: 접힘)                 │
│  - Header: [이름 뱃지] & [총금액] 만 미니멀 표시               │
│  - Body: 개인 정산표                                        │
│          - 맨 위 라인: 선입금 금액 & [선입금 컨펌] (독립 컨펌)  │
│          - 중간 라인: 차수별 참석 금액, 찬조할인, 수동조정       │
│          - 총합계 라인: 실납부 금액 & [최종 회비 컨펌]           │
│          - 하단 액션: [수동조정] 버튼                         │
│            └ 금액 입력, 미리보기, [같은 금액 일괄 적용] 체크박스, │
│              실시간 계산식(현재 - 조정 = 적용), confirm 확인팝업│
└─────────────────────────────────────────────────────────────┘
```

### 원터치 전체 토글 동작
* 상단 탭 바에서 `정산` 탭을 이미 선택한 상태에서 정산 탭 버튼을 다시 누르면:
  * 3개 섹션 중 하나라도 닫혀있으면 **모두 펼침**
  * 3개 섹션이 모두 열려있으면 **모두 접힘**
* 기본 로딩 상태: 3개 섹션 모두 **기본 접힘(`false`)**

## 2. 선입금 (Advance Deposit) 프로세스 사양

### (1) 일정 등록 및 기본정보 수정 연동
* 기존에 실제 알림 발송 기능이 없었던 `15분 전 알림` 필드를 완전히 제거하고 **`선입금` 입력 필드**로 교체하였습니다.
* **적용 위치**:
  * 신규 일정 등록 모달 (`MeetingsPage.jsx`)
  * 일정 기본정보 수정 폼 Row 6 (`MeetingDetailPage.jsx`)
  * 정산 탭 정산 내역의 `[+ 선입금 추가]` 모달

### (2) 선입금 뱃지 노출 (3개 장소)
1. **일정 목록 카드** (`MeetingsPage.jsx`): 모임 제목 앞 `[선입금 10,000원]` 하늘색 뱃지 표기
2. **일정 상세 헤더** (`MeetingDetailPage.jsx`): 모임 제목 앞 `[선입금 10,000원]` 뱃지 표기
3. **벙대기실 헤더** (`MeetingDetailPage.jsx`): 벙대기실 제목 앞 `[선입금 10,000원]` 뱃지 표기

### (3) 정산 계산 공식 및 차감 규칙 (`communityRules.js`)
* **선입금 차감 공식**:
  $$\text{최종 보낼 회비}(\text{netToPay}) = (\text{참석 차수별 합산액} - \text{찬조 할인} - \text{선결제액} \pm \text{수동 조정액}) - \text{선입금액}$$
* 선입금을 납부한 회원은 최종 회비 납부 시 이미 납부한 선입금만큼 차감된 금액만 총무에게 송금합니다.

### (4) 2단계 독립 컨펌 체계
* **1단계 선입금 컨펌**: 모임 전 회원이 선입금을 송금하고 [선입금 완료]를 누르면 총무가 확인 후 [선입금 컨펌]을 처리합니다.
* **2단계 최종 회비 컨펌**: 모임 종료 후 정산이 완료되면 차액을 송금하고 총무가 [최종 컨펌]을 처리합니다.
* 두 컨펌 상태는 서로 간섭하지 않고 독립적으로 동작합니다.

## 3. 정산표 및 비고(Notes) 실시간 저장 사양

### (1) 모임 전체 정산표 칼럼 구성
| 컬럼명 | 너비 | 표기 내용 | 비고 |
| :--- | :--- | :--- | :--- |
| **항목** | 80px | `1차`, `2차`, `찬조금`, `선입금`, `총합` | 고정 볼드 |
| **금액** | 100px | 해당 차수 지출액, 찬조 할인액(-), 선입금 총액, 총 지출액 | 숫자 포맷 |
| **내용** | 가변 | 차수별 참석자 이름 뱃지 열거, 찬조자 뱃지 및 찬조 메모, 선입금 컨펌 현황(`N명 컨펌 / 총 M명`) | 이름 뱃지 UI |
| **비고** | 140px | 벙주, 총무, 운영자 인라인 편집 가능 (`settle-note-input`) | onBlur 시 Firestore 실시간 저장 |

### (2) 비고(Settlement Notes) 저장 구조
Firestore `meetings/{meetingId}` 문서 내 `settlementNotes` 맵 필드에 저장됩니다:
```javascript
settlementNotes: {
  round_1: "1차 고기집 영수증 확인",
  round_2: "볼링장 게임비",
  sponsor_0: "총무님 음료 찬조",
  deposit: "선입금 계좌 확인 완료",
  total: "최종 마감 전 특이사항 없음"
}
```

## 4. 1-Line 찬조금 입력 폼 사양

* 기존의 공간을 많이 차지하던 세로형 폼을 제거하고, 정산표 바로 아래에 **1줄 가로 폼**을 배치하였습니다.
* **구성 필드**:
  1. `[찬조자 선택]`: 드롭다운 셀렉트 (`settle-input-tall`, 높이 38px)
  2. `[찬조 금액]`: 숫자 입력 (최소 1,000원 단위)
  3. `[내용 (선택)]`: 텍스트 인라인 입력
  4. `[추가]` 버튼: 기본 파랑 버튼
  5. `[취소]` 버튼: 아웃라인 버튼
* 모바일 환경에서도 손가락 터치 미스를 방지하기 위해 입력 필드 높이와 패딩을 최적화하였습니다.

## 5. 수동 금액 조정 (Manual Adjustment) 계산기 사양

총무나 벙주가 개별 참석자의 금액을 올리거나 깎아줄 때 사용하는 정밀 조정 도구입니다.

### (1) UI 구성
* 개인별 아코디언 내부 정산표 하단에 **[수동조정]** 버튼을 눌러야만 조정 패널이 열립니다.
* **필드 구성**:
  * 조정 금액 입력창 (`placeholder: "예: 1000 또는 -1000"`)
  * `[같은 금액에 일괄 적용]` 체크박스 (**기본값: 체크됨**)
  * `[미리보기]` 버튼
  * `[적용]` 버튼
* **실시간 계산식 가이드 박스**:
  $$\text{현재 금액 } (A) - \text{조정 금액 } (B) = \text{적용 금액 } (A - B)$$
  * 사용자가 숫자를 입력하는 즉시 적용 예정 금액이 실시간으로 계산되어 가이드 박스에 볼드로 표시됩니다.

### (2) 일괄 적용 처리 로직
* `같은 금액에 일괄 적용` 체크 시:
  * 현재 선택된 참석자와 `netToPay`가 동일한 모든 참석자들의 UID를 추출하여 동일한 조정액을 일괄 적용합니다.
* 적용 버튼 클릭 시:
  * 브라우저 `window.confirm` 대화상자로 확인 후 Firestore에 일괄 업데이트합니다.

## 6. 카드 헤더 48px 표준화 및 6px 간격 단일화 사양

### (1) 헤더 외형 높이 48px 단일화
* **대상 컴포넌트**: 장소 탭 차수 카드(`.lounge-round-accordion-header`), 정산 탭 3대 아코디언 카드(`.settle-accordion-header`).
* **규격**:
  * `height: 48px !important; min-height: 48px !important; max-height: 48px !important;`
  * `padding: 0 14px !important; box-sizing: border-box !important;`
  * `display: flex !important; align-items: center !important; justify-content: space-between !important;`
* **우측 제어 버튼 통일**:
  * `height: 28px !important; min-height: 28px !important; line-height: 26px !important; font-size: 11.5px !important;`
  * `white-space: nowrap !important; flex-wrap: nowrap !important;` (1줄 고정으로 내용물에 의한 상하 팽창 방지)
* **결과**: 장소 탭(`1차`, `2차`...)과 정산 탭(`나의 회비`, `정산 내역`, `개인별 내역`)의 모든 카드가 접힌 상태에서 **1px의 오차도 없이 동일한 48px 높이**를 유지합니다.

### (2) 상하 간격 6px 통일 규격 (Standard Gap = 6px)
* 벙대기실 5개 전체 탭(대화, 장소, 정산, 귀가, 앨범)의 상하 간격을 **제목 ↔ 서브탭 사이 간격(6px)**으로 단일화:
  1. `상단 캔버스` ↔ `제목 카드`: **6px**
  2. `제목 카드` ↔ `서브탭 바`: **6px** (기준 간격)
  3. `서브탭 바` ↔ `첫 번째 섹션`: **6px**
  4. `섹션` ↔ `섹션` 사이 간격: **6px** (`.lounge-unified-stack { gap: 6px !important; }`)
  5. `마지막 섹션` ↔ `+ 추가 버튼`: **6px**

## 7. 모바일 최적화 3컬럼 미니멀 정산표 (방안 A) 및 선입금 조건부 표시

모바일의 좁은 화면 폭에서 4개 컬럼(`항목 | 금액 | 내용 | 상태`) 표시 시 장소의 상세 주소 및 URL 텍스트로 인해 줄바꿈이 빈번하게 발생하고 가독성이 저하되던 문제를 해결하기 위해 영수증 형태의 **3컬럼 미니멀 정산표(방안 A)**를 구축하였습니다.

### (1) 선입금 조건부 표시 (Conditional Advance Deposit Row)
* **사양**: 선입금이 설정되지 않았거나 납부 금액이 없는 모임(`depositAmount === 0 && advanceDeposit === 0`)에서는 상단 선입금 행을 완전히 숨김 처리합니다.
* **효과**: 불필요한 `0원` 행이 사라지고 1차 참석 내역부터 즉시 표시되어 표가 한눈에 들어옵니다.

### (2) 3컬럼 컬럼 규격 및 레이아웃
| 컬럼명 | 너비 비율 | 텍스트 정렬 | 표시 내용 |
| :--- | :--- | :--- | :--- |
| **내역** | 52% | 좌측 정렬 | `[N차]` 회색 뱃지 + `순수 상호명` (장소 상세 주소 제외, 순수 상호명만 추출) / `선입금` 뱃지 + `모임 선입금` / `찬조/골든벨 할인` / `수동 조정` / `최종 보낼 회비` |
| **금액** | 28% | 우측 정렬 | 차수별 분담액, 선입금 차감액(-), 찬조 할인액(-), 수동 조정액(±), 최종 실납부 총액 (볼드 강조) |
| **상태/컨펌** | 20% | 중앙 정렬 | **나의 회비**: `참석` / `컨펌완료 ✓` / `입금완료` 버튼<br>**개인별 내역**: `참석` / `컨펌완료 ✓` / 총무 전용 `[컨펌]` / `[선입금 컨펌]` 원터치 버튼 |

### (3) 순수 상호명 추출 (`parsePlaceSummary`) 연동 및 1줄 고정 & 뱃지 찌그러짐 방지
* 카카오 지도나 네이버 플레이스에서 복사해 온 복잡한 주소 및 전화번호 텍스트가 장소명 필드에 포함되어 있더라도, `parsePlaceSummary(placeName)` 함수를 통해 **순수 식당/상호명(예: `대물조개전골등갈비`, `야키토리잔잔`)**만 깔끔하게 추출하여 1열 내역에 뱃지와 함께 렌더링합니다.
* **뱃지 줄바꿈 및 상호명 2줄 개행 방지 CSS**:
  - 테이블에 `table-layout: fixed; width: 100%;`를 적용하여 모바일 폭에서도 컬럼 너비(52%, 28%, 20%)가 깨지지 않도록 강제.
  - `.settle-place-cell`: `display: flex; align-items: center; gap: 6px; min-width: 0; width: 100%; overflow: hidden;`
  - `.settle-round-badge`: `font-size: 10.5px; font-weight: 700; padding: 1px 6px; white-space: nowrap !important; flex-shrink: 0 !important; min-width: 34px; height: 22px; line-height: 20px; box-sizing: border-box; display: inline-flex; align-items: center; justify-content: center; border-radius: 6px;` (세로 꺾임 '1 / 차' 완벽 차단)
  - `.settle-place-text`: `font-weight: 600; color: var(--color-text); font-size: 12.5px; white-space: nowrap !important; overflow: hidden !important; text-overflow: ellipsis !important; flex: 1; min-width: 0; display: block;` (상호명이 길어도 2줄로 꺾이지 않고 한 줄 고정 후 말줄임표 `...` 처리)

### (4) 적용 대상
* `[섹션 1] 나의 회비` 아코디언 내부 정산표
* `[섹션 3] 개인별 내역` 아코디언 내부 개별 참석자 정산표

## 8. 인포그래픽 정산 수식 바 및 2행 구조 정산 내역 테이블

### (1) 인포그래픽 수식 바 (0원 항목 스마트 숨김 & No-Scroll 컴팩트 바)
* **0원 항목 스마트 숨김**: 사전 지출, 찬조금, 선입금 중 금액이 `0원`인 항목과 연산자(`+`, `-`)를 자동으로 숨겨 노이즈를 제거합니다.
  * 일반 모임(사전지출/찬조/선입금 없음): `[차수 합산] = [1/N 정산액]` (단 2개 카드로 극도로 슬림)
  * 선입금 모임: `[차수 합산] - [선입금] = [1/N 정산액]` (3개 카드)
* **No-Scroll 반응형 설계**: 카드가 4개 이상이더라도 `flex: 1`, `min-width: 0`, 유동 폰트 크기 및 컴팩트 패딩으로 모바일 360px 폭에서도 **가로 스크롤 없이 100% 한 화면에 쏙 들어가도록** 구현되었습니다.

### (2) 2행 구조 정산 내역 테이블 & 방안 1 (상호명 1줄 고정 & 참석자 1줄 팝오버)
* **1행 (`settle-row-main`)**: 
  * `항목 / 장소` 너비를 56%로 대폭 확대하고 `white-space: nowrap; text-overflow: ellipsis;`를 적용하여 `대물조개전골등갈비` 등 긴 상호명이 **절대 2줄로 쪼개지지 않고 1줄로 단정하게 고정**됩니다.
  * `금액 (30%)`, `비고 (14%)` 컴팩트 인라인 배치.
* **2행 (`settle-row-sub`) [방안 1 Toss/Notion 스타일]**:
  * 참석자가 몇 명이든 **무조건 1줄로 고정**: `[참석 10명]` 칩 + `스캇, 별, 로이 외 7명 ▸`
  * 해당 요약 칩을 터치하면 바로 아래에 세련된 플로팅 팝오버(`settle-attendee-popover`)가 열려 전체 참석자 명단 뱃지를 시원하게 확인 가능.
  * 대형 정모(20~50명)에서도 테이블이 세로로 길어지거나 복잡해지지 않고 영수증처럼 완벽한 비례를 유지합니다.
* **정렬 툴바**: `차수순(기본)`, `금액높은순`, `인원많은순` 원터치 필터 제공.

### (3) 사전 지출 (Pre-Expense) 관리 시스템
* 모임 전 발생한 지출(장소 대관비, 예약금, 물품 구매 등)을 모임 정산에 공식 반영:
  * 빠른 선택 퀵 태그 버튼: `장소 대관비`, `예약금`, `물품 구매`, `간식·음료`, `기타 사전지출`
  * 결제자(대납자) 지정: 실시간 회원 검색기(`admin-edit-search-box`) 연동
  * 회계 반영 공식:
    $$\text{사전 지출액은 전체 1/N 분담 총액에 합산} \quad \& \quad \text{결제자는 본인 부담금에서 선결제액만큼 차감(환급)}$$
  * 삭제 기능: 등록된 사전 지출 항목은 언제든 총무/관리자가 즉시 삭제 가능.

### (4) 회원 검색형 선택기 및 선입금 추가 버튼 정리
* 찬조 추가 및 사전 지출 결제자 선택 시 기존 드롭다운 대신 실시간 검색기 탑재.
* 일정 등록 시 선입금을 입력하므로 중복되던 `+ 선입금 추가` 버튼은 제거.

## 9. 개인별 내역 디자인 테마 & 수동 조정 패널 3행 개편

### (1) 상태별 감성 파스텔 틴트 카드 테마
* 참석자의 입금 상태에 따라 직관적인 시각 피드백을 제공:
  * **컨펌완료**: 연민트 배경 (`#f0fdf4`), 그린 보더 (`#bbf7d0`)
  * **입금확인중**: 웜크림 배경 (`#fffbeb`), 옐로우 보더 (`#fde68a`)
  * **환급 대상자**: 소프트블루 배경 (`#f0f9ff`), 스카이 보더 (`#bae6fd`)
  * **미입금/기본**: 순백색 (`#ffffff`), 뉴트럴 보더 (`#e2e8f0`)

### (2) 개인 아코디언 타이틀(헤더) 마이크로 뱃지 복원
* 카드가 접힌 상태에서도 핵심 정보를 한눈에 파악할 수 있도록 1줄 뱃지 복원:
  * `실명` + `참석 차수 칩 ([1차], [2차])` + `선입금 칩 (조건부)` + `상태 태그 (컨펌완료 ✓, 입금확인중, 환급대상, 미입금)` + `최종 회비(볼드)`

### (3) 수동 조정 패널 3행 구조 개편
* 기존의 불필요한 '미리보기' 버튼을 삭제하고, 3행 레이아웃으로 직관화:
  * **1행**: 실시간 산출식 박스 (`현재 금액 - 조정 금액 = 적용 금액 (동일 금액 적용 대상자 명단 포함)`)
  * **2행**: `[✓] 현재 회비 동일 참석자 일괄 적용 (N명)` 체크박스
  * **3행**: `조정 금액 입력창` + `[적용]` 버튼

### (4) 참석자 검색 및 정렬 툴바
* 상단 검색창: 이름, 닉네임 실시간 필터링
* 정렬 필터: `기본(등록순)`, `미컨펌순`, `금액순`, `이름순` 원터치 토글

## 10. 마감 탭 (구 귀가 탭) 개편 및 벙점수 (Bung Score) 규격

### (1) 공식 용어 정의: `벙점수` (Bung Score)
* 벙(모임) 참석을 통해 생성·부여되는 모든 점수를 공식적으로 **`벙점수`**라고 명칭합니다.
  * **기본 벙점수**: 모임 참석 확정 시 **+1점**
  * **타 권역 원정 벙점수**: 타 도/권역 모임 참석 시 **+1점 추가 (총 2점)**
  * **해외 친구/원정 벙점수**: 해외 모임 또는 해외 거주자 참석 시 **+2점 추가 (총 3점)**
  * **누적 벙점수 (`totalScore`)**: `기본 벙점수 + 원정 벙점수 + 이벤트 점수`

### (2) 마감 탭 참가자 리스트 정렬 & 벙점수 표기 규격
1. **정렬 우선순위**:
   * 1순위: 현재 접속한 **본인**
   * 2순위: **운영진** (방장/부방장)
   * 3순위: 나머지 참가자 **가나다순**
2. **벙점수 변화 표기**:
   * 이름과 같은 행에 숫자만 `현재 벙점수 → 반영 후 벙점수` 형태로 표기 (`tabular-nums` 적용).
   * 자릿수에 관계없이 숫자의 시작과 끝 위치가 수직으로 완벽하게 일치하도록 고정폭 배치.

### (3) 승급 및 마일스톤 뱃지 획득 알림 섹션 & 영구 보존 규격
* `내 안심 귀가 상태` 섹션 바로 아래에 배치:
  * 참가자 중 **신입(`Rookie`) → 정회원(`Member`) 승급자** 또는 **마일스톤 티어 뱃지(`얼룩말, 달리는말 등`) 변경자**가 발생했을 때 동적으로 축하 카드를 노출.
  * 변경자가 없을 때는 영역이 완전히 숨겨집니다.
* **타임라인 기반 역사적 점수 & 승급 영구 보존 (`getHistoricalScoreInfo`)**:
  * 회원이 시간이 흘러 수많은 벙에 참석하여 총점이 증가하더라도, 과거 벙을 열람했을 때 그 당시 시점의 점수 변화(`0 → 1`, `9 → 10` 등)와 승급 기록이 뭉개지지 않고 영구 보존.
  * 기존 850여 개 과거 벙은 타임라인 누적 역산을 통해 당시 점수와 신입 승급(`priorCount === 0`)을 복원.
  * 신규 마감 벙은 모임 객체에 `memberScoreSnapshots` 및 `rookiePromotedUids`를 영구 스냅샷으로 저장.
  * 마감 친구 리스트 행(Row)에도 각 참가자 이름 옆에 `[정회원 승급 🎊]` 및 `[티어 뱃지 달성 ⭐]` 뱃지를 직접 노출하여 시각적 직관성을 보장.

## 11. 모임 마감 시 기능 잠금 & 운영진 수정 모드

### (1) 마감 시 전체 기능 잠금 (Lock-down)
* **벙주**: 모임 마감(`status === 'settled'`) 후 일정 수정/삭제 불가 (버튼 완전 숨김).
* **장소 탭**: `+ N차 추가` 및 차수별 `편집` 숨김, 참석 토글 잠금.
* **대화 탭**: 입력창 및 사진 첨부 비활성화 (`"마감된 모임입니다. (대화 비활성화)"`).
* **정산 탭**: `+ 찬조 추가`, `+ 사전지출 추가`, `수동조정`, 비고 수정 잠금. 미입금자 및 선입금은 마감 시 일괄 입금/컨펌 처리.
* **마감 탭**: `귀가완료 체크` 버튼 잠금 (`귀가완료 ✓`).
* **앨범 탭**: 미디어 업로드는 유지되나 삭제 기능은 비활성화.
* **제목 헤더**: 진행 뱃지가 `종료`로 변경되고 드라이버 버튼 비활성화.

### (2) 운영진 수정 및 롤백 모드 (A2 합의안)
* 운영진(부방장/방장)이 마감된 벙대기실에 입장하면 상단에 **`[운영진 수정]`** 버튼이 노출.
* 클릭 시 확인 팝업 후 모임을 오픈 상태로 전환하고 이미 지급된 벙점수를 차감/롤백하여 운영진이 자유롭게 수정한 뒤 다시 최종 마감할 수 있도록 지원.
* **방장 전용 권한**: 일정 상세 페이지에서 모임 **삭제** 버튼은 최고 운영자(방장)에게만 노출.

## 12. 최종 마감 처리 및 모임 라이프사이클 동기화 규격 (Subway Route & Lifecycle Specification)

### (1) 지하철 노선도바(Subway Route Progress) 종료 자동 전환 보장
* **최종 마감 시점 (`settleMeetingWithScores`)**:
  * 운영진이 정산 페이지에서 최종 마감 버튼을 누르면, 모임 데이터의 `metroStep`을 **`numRounds + 1` (최종 종료 단계)**로 자동 갱신하고, 모든 차수 라운드의 상태를 `status: 'ended'`로 일괄 저장(Local Storage 및 Firestore Batch Commit).
* **마감 벙 열람 시 100% 종료 게이지 보장 (`MeetingDetailPage.jsx`)**:
  * 과거 데이터나 필드 동기화 오차로 인해 `meeting.metroStep`에 이전 차수(예: 1차) 값이 남아있더라도, `meeting.status === 'settled'`를 최우선으로 평가하여 지하철 노선도 진행도를 무조건 **종료 단계(`maxMetroStep`, 게이지 100% 채움)**로 표시합니다.

### (2) 미귀가자 시간 강제 주입 배제 (순수 본인 귀가 시간 보존 원칙)
* **원칙**: 운영진이 최종 마감 버튼을 누를 때, 본인이 직접 '귀가완료'를 누르지 않은 회원에게 **운영진의 마감 시각(예: `23:45 귀가완료`)을 일괄 강제 주입하던 레거시 로직을 완전히 제거**하였습니다.
* **보존 규칙**:
  * 회원이 모임 중 직접 [귀가완료] 버튼을 누른 경우에만 그 시각(`safeReturns[uid]`)이 영구 보존됩니다.
  * 누르지 않은 회원은 미귀가 상태를 유지하며, 타인의 조작 시각으로 덮어써지지 않습니다.

### (3) 대기실 목록(`HomePage.jsx`)의 마감 벙 배지 정합성
* 홈 화면의 오픈 벙대기실 목록에서 마감된 모임(`status === 'settled'`) 열람 시, 참가자 본인이라 하더라도 진행 중인 방으로 착각하지 않도록 **`[참석 중]` 배지를 노출하지 않고 `[마감]` 배지만 단독 표출**합니다 (`m.status !== 'settled' && isAttendee`).
