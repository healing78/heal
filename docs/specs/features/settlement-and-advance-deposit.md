# 벙대기실 정산탭 및 선입금·정산표 기능 명세서 (Settlement & Advance Deposit Specification)

> **문서 목적:**  
> 벙대기실(`MeetingDetailPage.jsx`)의 정산 탭 구조 개편, 선입금(Advance Deposit) 전체 라이프사이클 관리, 모임 및 개인 정산표, 1열 인라인 찬조금 입력, 비고 실시간 저장, 수동조정 일괄 적용 로직을 영구히 기록하고 유지보수할 수 있도록 표준 사양을 정의합니다.

---

## 1. 정산 탭 3대 아코디언 카드 아키텍처

기존의 4개 영역(나의 회비, 3대 요약 카드, 참석자 목록, 하단 설정 서랍)으로 파편화되어 있던 UI를 **3개의 독립 아코디언 카드**로 통합하였습니다.

```
┌─────────────────────────────────────────────────────────────┐
│ [섹션 1] 나의 회비 아코디언 카드 (기본: 접힘)                  │
│  - Header: 선입금 상태/버튼 | 최종 회비 | [입금 완료] 버튼      │
│  - Body: 내 상세 정산표 (선입금, 차수별, 찬조할인, 수동조정, 총합)│
├─────────────────────────────────────────────────────────────┤
│ [섹션 2] 정산 내역 아코디언 카드 (기본: 접힘)                  │
│  - Header: 총무 입금 계좌 | [계좌 복사] | [내 계좌] 버튼       │
│  - Body: 3개 요약 카드 (총지출, 찬조, 1/N 대상액)              │
│          모임 전체 정산표 (항목, 금액, 내용[뱃지], 비고[실시간])│
│          하단 액션: [+ 찬조 추가] [+ 선입금 추가] [정산서 복사]  │
│          1-Line 찬조/선입금 인라인 폼                        │
├─────────────────────────────────────────────────────────────┤
│ [섹션 3] 개인별 내역 아코디언 카드 (기본: 접힘)                 │
│  - Header: [이름 뱃지] & [총금액] 만 미니멀 표시               │
│  - Body: 개인 정산표                                        │
│          - 맨 위 라인: 선입금 금액 & [선입금 컨펌] (독립 컨펌)  │
│          - 중간 라인: 차수별 참석 금액, 찬조할인, 수동조정       │
│          - 총합계 라인: 실납부 금액 & [최종 회비 컨펌]           │
│          - 하단 액션: [수동조정] 버튼                         │
│            └ 금액 입력, 미리보기, [같은 금액 일괄 적용] 체크박스, │
│              실시간 계산식(현재 - 조정 = 적용), confirm 확인팝업│
└─────────────────────────────────────────────────────────────┘
```

### 원터치 전체 토글 동작
* 상단 탭 바에서 `정산` 탭을 이미 선택한 상태에서 정산 탭 버튼을 다시 누르면:
  * 3개 섹션 중 하나라도 닫혀있으면 **모두 펼침**
  * 3개 섹션이 모두 열려있으면 **모두 접힘**
* 기본 로딩 상태: 3개 섹션 모두 **기본 접힘(`false`)**

## 2. 선입금 (Advance Deposit) 프로세스 사양

### (1) 일정 등록 및 기본정보 수정 연동
* 기존에 실제 알림 발송 기능이 없었던 `15분 전 알림` 필드를 완전히 제거하고 **`선입금` 입력 필드**로 교체하였습니다.
* **적용 위치**:
  * 신규 일정 등록 모달 (`MeetingsPage.jsx`)
  * 일정 기본정보 수정 폼 Row 6 (`MeetingDetailPage.jsx`)
  * 정산 탭 정산 내역의 `[+ 선입금 추가]` 모달

### (2) 선입금 뱃지 노출 (3개 장소)
1. **일정 목록 카드** (`MeetingsPage.jsx`): 모임 제목 앞 `[선입금 10,000원]` 하늘색 뱃지 표기
2. **일정 상세 헤더** (`MeetingDetailPage.jsx`): 모임 제목 앞 `[선입금 10,000원]` 뱃지 표기
3. **벙대기실 헤더** (`MeetingDetailPage.jsx`): 벙대기실 제목 앞 `[선입금 10,000원]` 뱃지 표기

### (3) 정산 계산 공식 및 차감 규칙 (`communityRules.js`)
* **선입금 차감 공식**:
  $$\text{최종 보낼 회비}(\text{netToPay}) = (\text{참석 차수별 합산액} - \text{찬조 할인} - \text{선결제액} \pm \text{수동 조정액}) - \text{선입금액}$$
* 선입금을 납부한 회원은 최종 회비 납부 시 이미 납부한 선입금만큼 차감된 금액만 총무에게 송금합니다.

### (4) 2단계 독립 컨펌 체계
* **1단계 선입금 컨펌**: 모임 전 회원이 선입금을 송금하고 [선입금 완료]를 누르면 총무가 확인 후 [선입금 컨펌]을 처리합니다.
* **2단계 최종 회비 컨펌**: 모임 종료 후 정산이 완료되면 차액을 송금하고 총무가 [최종 컨펌]을 처리합니다.
* 두 컨펌 상태는 서로 간섭하지 않고 독립적으로 동작합니다.

## 3. 정산표 및 비고(Notes) 실시간 저장 사양

### (1) 모임 전체 정산표 칼럼 구성
| 컬럼명 | 너비 | 표기 내용 | 비고 |
| :--- | :--- | :--- | :--- |
| **항목** | 80px | `1차`, `2차`, `찬조금`, `선입금`, `총합` | 고정 볼드 |
| **금액** | 100px | 해당 차수 지출액, 찬조 할인액(-), 선입금 총액, 총 지출액 | 숫자 포맷 |
| **내용** | 가변 | 차수별 참석자 이름 뱃지 열거, 찬조자 뱃지 및 찬조 메모, 선입금 컨펌 현황(`N명 컨펌 / 총 M명`) | 이름 뱃지 UI |
| **비고** | 140px | 벙주, 총무, 운영자 인라인 편집 가능 (`settle-note-input`) | onBlur 시 Firestore 실시간 저장 |

### (2) 비고(Settlement Notes) 저장 구조
Firestore `meetings/{meetingId}` 문서 내 `settlementNotes` 맵 필드에 저장됩니다:
```javascript
settlementNotes: {
  round_1: "1차 고기집 영수증 확인",
  round_2: "볼링장 게임비",
  sponsor_0: "총무님 음료 찬조",
  deposit: "선입금 계좌 확인 완료",
  total: "최종 마감 전 특이사항 없음"
}
```

## 4. 1-Line 찬조금 입력 폼 사양

* 기존의 공간을 많이 차지하던 세로형 폼을 제거하고, 정산표 바로 아래에 **1줄 가로 폼**을 배치하였습니다.
* **구성 필드**:
  1. `[찬조자 선택]`: 드롭다운 셀렉트 (`settle-input-tall`, 높이 38px)
  2. `[찬조 금액]`: 숫자 입력 (최소 1,000원 단위)
  3. `[내용 (선택)]`: 텍스트 인라인 입력
  4. `[추가]` 버튼: 기본 파랑 버튼
  5. `[취소]` 버튼: 아웃라인 버튼
* 모바일 환경에서도 손가락 터치 미스를 방지하기 위해 입력 필드 높이와 패딩을 최적화하였습니다.

## 5. 수동 금액 조정 (Manual Adjustment) 계산기 사양

총무나 벙주가 개별 참석자의 금액을 올리거나 깎아줄 때 사용하는 정밀 조정 도구입니다.

### (1) UI 구성
* 개인별 아코디언 내부 정산표 하단에 **[수동조정]** 버튼을 눌러야만 조정 패널이 열립니다.
* **필드 구성**:
  * 조정 금액 입력창 (`placeholder: "예: 1000 또는 -1000"`)
  * `[같은 금액에 일괄 적용]` 체크박스 (**기본값: 체크됨**)
  * `[미리보기]` 버튼
  * `[적용]` 버튼
* **실시간 계산식 가이드 박스**:
  $$\text{현재 금액 } (A) - \text{조정 금액 } (B) = \text{적용 금액 } (A - B)$$
  * 사용자가 숫자를 입력하는 즉시 적용 예정 금액이 실시간으로 계산되어 가이드 박스에 볼드로 표시됩니다.

### (2) 일괄 적용 처리 로직
* `같은 금액에 일괄 적용` 체크 시:
  * 현재 선택된 참석자와 `netToPay`가 동일한 모든 참석자들의 UID를 추출하여 동일한 조정액을 일괄 적용합니다.
* 적용 버튼 클릭 시:
  * 브라우저 `window.confirm` 대화상자로 확인 후 Firestore에 일괄 업데이트합니다.
